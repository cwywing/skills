# 文档鉴别材料生成 Prompt

将本文件与 `md素材/codebase_data.json` 一并作为上下文，生成《文档鉴别材料》。

> 数据来源：`software_info`、`models`、`controllers`、`services`、`routes`、`frontend`；勿臆造不存在的模块。  
> **强制**：结构见 `references/document-generation.md`；脱敏见 `references/content-redaction.md`。

---

## 任务目标

生成完整软件说明书（Word ≥60 页），**先背景与流程、后模块索引**，可打印。

分段保存到 `md素材/`：

- `document_identification-1.md` … 必要时 `-4`～`-6`

---

## 文档结构（必须按此顺序，禁止模块优先）

# 文档鉴别材料（软件说明文档）

## 说明

以下内容为本软件的说明文档材料，用于软件著作权登记鉴别。

权利人署名: {基础资料.著作权人}
软件名称: {基础资料.软件全称}
软件版本号: {基础资料.版本号}

---

## 1. 软件概述

- 全称 / 简称 / 版本（来自 `software_info`）
- 用途、服务对象
- **首页「说明」已含权利人署名**；其余章节默认不重复单位全称

## 2. 项目背景（必须写厚）

- 行业与业务语境
- 建设前痛点（条列，具体）
- 建设目标
- 范围边界：本软件做什么 / 外部系统仍做什么

## 3. 总体业务蓝图（先连起来）

- 端到端主链路（ASCII 或分步文字）
- 角色如何参与
- 3～4 个典型故事（端到端，少堆类名）

## 4. 系统总体设计

- 架构定位、逻辑结构、数据流向
- 与外部系统职责对照表
- 技术约定（幂等、队列、统一响应等，以代码为准）

## 5. 按流程详解（主文，必须具体）

每条流程固定四段：**触发 → 步骤 → 关键规则 → 结果/异常**。

从代码真实能力归纳流程，例如（按项目裁剪，有则写）：

- 主数据/工单同步
- 上游单据接入与自动创单
- 现场日志/消息通知
- 报告同步与回写闭环
- 审批回调与人员状态
- 标准工时 / 巡检等衍生流程（有则单列）
- 文件产出（PDF/ZIP 等）
- 运维与日志

**禁止**用「见某模块」一句带过替代步骤说明。

## 6. 功能模块对照（后置）

- 模块表：名称、入口、**对应哪条流程**
- 控制器/路由/服务索引（短）
- 定时任务列表

## 7. 数据库设计说明

- 表一览、关联、字段说明（可摘数据字典）

## 8. 系统运行环境

- 来自 `software_info`；依赖可读 composer/package

## 9. 主要界面说明

- 仅描述本仓库真实页面/邮件模板；无前端则如实写「以 API 与邮件为主」

## 10. 用户使用方法

- IT 对接 / 业务人员；注意事项

## 11. 软件特色与创新点

- 与第 2 章痛点一一对应更佳

---

## 格式与质量

- 充分展开；Markdown 分级清晰；流程用文字/ASCII
- 禁止密钥、绝对本地路径、未要求的单位全称堆砌
- 与 JSON/代码一致

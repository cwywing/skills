# Phase 2a：核心业务文件筛选

目标：产出 `md素材/core_business_files.json`，供程序鉴别材料脚本读取。

全量扫描会混入样式、装饰组件与非核心页，导致材料灌水且前后端比例失衡。由 LLM 做语义筛选，再由脚本机械抽取。**与具体框架无关**：按「领域独创性」选相对路径，而不是按目录名是否叫 Controller。

> **前置：若项目基于开源框架 / 开源插件 / 公开模板二开**，必须先读 `fork-detection.md`，**排除上游原生代码**，仅保留本项目定制代码。`分类` 只写功能名，**不要**写「(二开)」——程序段标题由脚本输出为 `分类：相对路径`。

---

## 质量优先原则（强制）

程序鉴别材料要体现**独创业务特征**，不是堆框架样板。选文件时按下列优先级：

| 优先级 | 保留（高） | 靠后 / 尽量少选（低） |
|--------|------------|----------------------|
| 1 | 领域算法与状态机：计价/折扣、库存或额度扣补、支付/回调幂等、审批流转、积分或余额快照等 | 重复的路由/URL 拼接块、纯配置罗列 |
| 2 | 特征明显的领域服务 / Model / UseCase 业务方法 | 标准列表：筛选 + 分页 + 批量删除的同构 CRUD |
| 3 | 含事务、快照、幂等、权限校验的核心链路 | 空壳转发入口、仅委托下一层的薄封装 |
| 4 | 少量能展示业务交互的前端/客户端界面 | 大段重复的列表模板（表头+筛选+分页结构雷同） |

**Contrast：**

- Correct：本项目特有的计价规则、状态迁移、幂等入账、跨系统同步中的业务分支
- Incorrect：整篇都是列表页 + 通用权限 if + 空壳入口
- Rationale：审查看的是「这软件独特在哪」；样板占比过高会显得材料质量差

**选入前自问（每个文件）：**

1. 去掉框架样板后，还剩没有本项目特有业务逻辑？
2. 与已选文件是否高度同构（又一个 list/form CRUD）？
3. 若只能保留 10 个文件，它是否仍会入选？

---

## 三次审查（强制，生成 Word/PDF 之前）

筛选并写出 `core_business_files.json` 后，**至少三次审查**通过，才允许跑 `generate_program_identification.py`；**再**脱敏 → Word → PDF。禁止「一筛完立刻出 PDF」。

| 轮次 | 审查焦点 | 不通过则 |
|------|----------|----------|
| 第 1 次 | 样板占比：同构列表、空壳转发、纯路由拼接是否过多 | 替换为领域服务/核心算法文件 |
| 第 2 次 | 业务特征：说明书声称的独创点是否在源码中覆盖；文件间是否重复同构 | 增补特征文件、删同构列表 |
| 第 3 次 | 体量与比例：估页 80～100；主程序侧（后端数组）≥40%；路径存在；无上游原生；分类无「二开」 | 加减文件至达标 |

三次审查结论应简要记录（写在 JSON `审查记录` 或对话中），再进入 Phase 2b。

## 数量与比例（校准到 PDF 页数）

| 指标 | 建议区间 | 原因 |
|------|----------|------|
| 前端文件数 | **少而精**（宁缺列表页） | 界面层易堆重复模板 |
| 后端文件数 | 优先领域服务 / 核心入口 | 体现独创逻辑 |
| 合计源码行 | 约 **4000～6500** | 初估用；**以 `export_identification_pdf.py` 实测页数为准** |
| 后端行数占比 | ≥ 40% | 避免「全是界面」印象；纯后端可为 100% |
| 程序 PDF 页数 | **80～100** | 至少 80，不超过 100 |

**估页校准（强制闭环）：** generate 脚本常按约 50 行/页估算，实际 Word 导出常见约 **55～70 行/页**（同文件数下脚本估页会偏高）。流程：选码 → generate → redact → md2docx → **export 看实测页数** → 超 100 再砍同构/大页，不足 80 再补特征文件后重导。禁止只信脚本估页就定稿。

无独立前端或 fork 排除 UniApp 时：`前端文件` 可为 `[]`；定制 PC/服务端模板放入 `后端文件` 即可（字段名是历史约定）。

若后端占比不足：优先删前端大页。总量过大：先砍同构列表。总量不足：补**特征业务算法文件**，不要用第三个同构 list 入口凑页，**不要**回退收录开源原生。

异栈目录名不同时：把「主业务实现」放进 `后端文件`，「界面/客户端」放进 `前端文件`（字段名是历史约定，不表示必须用某框架）。

## 筛选规则（通用）

| 区域 | 保留 | 排除 |
|------|------|------|
| 界面 / pages / views / screens | 核心业务交互（少而精） | 纯装饰、高度重复列表页 |
| 组件 / widgets | 支付、购物车、审批等业务组件 | 纯 UI 装饰、无关通用弹层 |
| api / store / utils 客户端封装 | 与核心链路相关 | 临时调试脚本 |
| 服务端 controller / handler / service / model / usecase | **业务算法与状态流转** | 框架基类、空壳、vendor/node_modules、同构 CRUD |

具体目录映射见 `framework-adapters.md`。

## Explore / 分析 Prompt 模板

### 前端 / 客户端

```
请分析 {前端项目路径} ，找出核心业务代码文件。
项目：{软件全称}；核心业务：{主要功能要点}

筛选规则（质量优先）：
- 优先：含独特交互的业务页/界面
- 靠后：结构雷同的列表页、大段样板布局
- 宁少勿滥：只选能代表业务特征的少量文件

输出：分类 + 相对项目根的路径（一行一个）。
```

### 后端 / 主程序侧

```
请分析 {后端项目路径} ，找出核心业务代码文件。
核心业务：{主要功能要点}

筛选规则（质量优先）：
- 优先：领域服务中的计价、额度/库存、折扣选取、支付幂等、余额快照、审批流转等
- 靠后：仅 list/add/edit/delete 的同构入口、大段路由拼接、通用权限样板
- 排除：框架自带基类、依赖目录、空壳转发

输出：分类 + 相对项目根的路径。
```

## JSON 格式（必须）

路径必须是**相对项目根**的相对路径，禁止绝对路径。

```json
{
  "说明": "核心业务代码文件清单；已排除开源上游；分类为功能名；已按独创业务优先三次审查",
  "生成时间": "YYYY-MM-DD",
  "审查记录": [
    "第1次：替换样板列表入口为领域服务",
    "第2次：覆盖说明书中的独创特征点",
    "第3次：体量约80～100页、后端数组≥40%"
  ],
  "前端文件": [
    {"分类": "结算确认页", "路径": "pages/checkout/confirm.vue"}
  ],
  "后端文件": [
    {"分类": "订单计价服务", "路径": "app/Services/OrderPricingService.php"}
  ]
}
```

上例路径仅为格式示意；**以当前仓库真实相对路径为准**，扩展名随语言变化。

`分类` 会写入代码段标题；脚本最终输出为：

```
/* ======= {分类}：{相对路径} ======= */
```

数组顺序即输出顺序。**禁止**在 `分类` 中写 `(二开)` / `(二开新增)`。

可参考 `assets/core_business_files.template.json`；需要带审查记录的完整示意时对照 `assets/demos/*/core_business_files.json`（路径须改成当前仓库真实文件）。

## 写入前自检

- [ ] 每个路径在对应项目根下真实存在
- [ ] 无 `node_modules` / `vendor` / `.git` / 构建产物目录内文件
- [ ] 体量支撑程序 PDF 80～100 页；后端数组占比 ≥40%（或纯后端）
- [ ] `分类` 无「(二开)」字样
- [ ] **已完成三次审查**（样板占比 → 业务特征 → 体量比例）
- [ ] 样板/同构列表代码未占主导
- [ ] 已写入 `md素材/core_business_files.json`

---

## 对比：正确 vs 错误

- Correct：`"路径": "src/domain/order/InventoryGuard.ts"`（含扣补/快照）；`"分类": "库存守卫"`
- Incorrect：连续三个几乎同构的后台 list 入口凑页；或绝对路径；或照抄他项目路径
- Rationale：独创业务优先于样板凑页；相对路径可移植且必须属于本仓库。

# 易驳回补正点（名称说明 + 运行截图）

法规（《计算机软件著作权登记办法》第十条）只要求交「程序 + **任一种**文档」的鉴别材料，**没有**写死「所有软件都必须交运行截图」。  
审查实务把文档分成两条路；走错路、或缺该路该有的材料，就会下发补正。本文件固化两条已实测会卡住的点。以版权中心当次通知书为准；本 skill 不保证通过。

**何时读：** Phase 0 定文档类型；Phase 3 写说明书；用户拿出补正通知书时。

---

## 1. 两条文档路（先定型，再决定要不要截图）

| 软件形态 | 走哪条文档 | 运行截图 |
|----------|------------|----------|
| 小程序、APP、Web、管理后台、有登录/主界面的业务系统 | **操作手册 / 使用说明**（可仍保留设计章节，但必须当操作手册补图） | **强制**：真实运行的完整、清晰界面；连贯流程；覆盖申请表主要功能 |
| 纯服务端、批处理、无图形界面的 API/插件/算法/嵌入式 | **设计说明书** | **不要编界面**。用结构图、流程图、时序图、接口与运行设计。嵌入式无界面可另交盖章《无操作界面说明》 |
| 名称含自创品牌词、音译、外文标识（如「安宜思」对应 EINS） | 与上表并行 | 「其他相关证明文件」交《软件名称说明》或商标注册证 |

**判定「有没有人机界面」：** 看**申请表软件名称 + 实际交付物**，不是看仓库里有没有前端目录。登记对象写「…小程序软件 / APP / 管理系统」= 有界面。只登记「…接口服务软件 / 数据处理软件」且确无操作界面，才走无界面路。

`基础资料.md` 须同时填：

- `文档类型:` `操作手册` 或 `设计说明书`
- `有人机界面:` `是` 或 `否`（与文档类型一致；旧稿若写 `有无图形界面` 视同本键）
- `名称需说明的品牌词:` 无则留空

禁止「有小程序却填否 / 设计说明书」来逃避截图。

### 为何上次小程序没要截图、这次要了

审查员对「任一种文档」有裁量：有人把偏设计说明书的纯文字交上去也能过。  
**不能赌裁量。** 通知书一旦写「文档鉴别材料缺少软件运行截图」，说明本次按**操作手册**审：有界面却只有文字描述界面，就会补正。有 UI 的软件，本流程**一律**按必须交真机截图执行。

## 2. 有人机界面：运行截图硬规则

补正原文常见：「请结合申请表填写的软件主要功能和技术特点、源程序量等，提交详细软件文档鉴别材料，截取软件真实运行的完整、清晰界面，展现连贯使用流程和全部功能。」

### 必须做到

1. **真机或开发者工具预览的实际运行图**，不要设计稿、不要原型、不要 PS/拼接。状态栏时间不要多张图完全同一秒（易被疑拼接）。
2. **完整界面**：含标题栏/导航、底部 Tab、主要按钮；不要只裁一块按钮。
3. **连贯流程**：登录（或进入）→ 主界面 → 分类/检索 → 详情 → 核心单据（购物车/报价/下单/支付/订单等）→ 个人中心/其它申请表功能。顺序要像真人在用。
4. **覆盖申请表「主要功能」每一条**；技术特点能在界面上看到的（如微信支付、微信登录）也要有对应画面。申请表写了积分/资料/资讯，就必须有对应截图。
5. **图文对应**：每张图下方 **3～5 句**：本屏有哪些按钮/菜单、点了发生什么、与哪条主要功能对应、与上一屏如何跳转。禁止「见上图」一句带过。
6. **截图位置**：审查常看文档**前 30 页和后 30 页**。只把图堆在文末、前 30 页仍是纯文字，可能再次补正。总览图放概述之后；连贯流程章可在后部，但前后两段都要有图。**不要**把全部截图只放在 `document_identification-5.md`（文末专章无法保证前 30 页有图）。
7. **名称一致**：截图里可见的软件名/简称须能对上申请表全称或简称；页眉全称+版本号。
8. **平台一致**：申请表运行平台写微信小程序/Android，勿交明显不符的 iOS 桌面截图；移动端优先竖屏。
9. **数量**：复杂业务系统宜 **15～30 张**（覆盖申请表主要功能即可，不是越多越好）；简单工具至少 **3～5 张**核心界面。
10. **禁止**用 AI 生成假界面、设计稿、PS 拼接冒充运行截图。ASCII 线框只可用于架构/流程章加厚，**不能替代**真机图。

### 做不到时

缺图就停：列出文件名清单，等用户把 PNG 放到 `md素材/screenshots/`，再 `md2docx` / 导出 PDF。Word 里出现「【缺图】」的稿**禁止**当补正件上传。

可选缺项（页面线上已关闭或无数据）：引导页、物流轨迹、线下转账页。申请表写过的主功能不能缺。

`md2docx.py` 支持 `![图注](screenshots/xxx.png)`；竖屏小程序图宽约 7.8cm。插图段落由脚本设为**单倍行距**——正文 Normal 是固定 13 磅，继承后会把图压成一条细黑线，看起来像「没占位」。导完 Word 后抽查概述后第一张图：高度应约 7～17cm，不能是一行字那么高。

### 同一张图不要贴三遍

审查要的是「前 30 页能看见界面」+「流程能看懂」，不是把同一套 PNG 复制到总览、界面章、附录各一遍。

| 位置 | 贴什么 |
|------|--------|
| 概述后总览（前 30 页） | **精选**覆盖申请表主要功能的若干张（不必全量） |
| 流程/使用专章 | 按操作顺序**逐步贴全**，每张有图注 |
| 其它章节 | 需要时引用图号即可，不要再嵌同一文件 |

同一 PNG 最多出现在「总览 + 对应流程」两处。三处全贴会把 PDF 页数和体积抬虚高，并不加分。

### 界面可见名称 / 版本号

截图里能读到的软件名、简称、版本号须能对上申请表：

- 界面写英文标识、申请表写音译中文：图注写清对应关系，并在《软件名称说明》里交代；能改界面文案则改。
- 个人中心/关于页若显示 `V1.30` 而申请表是 `V1.0.0`，审查可能认为不是同一软件。能改就改成申请表版本再截；改不了则在图注说明「界面构建号，登记版本以申请表为准」——仍优先改界面。

## 3. 无图形界面：不要用截图硬凑

纯服务端没有「运行界面」可截。补一张无关的 Postman/Swagger/服务器桌面，反而像套模板。

正确做法：

- 说明书按**设计说明书**：总体结构、模块与接口、关键算法/状态机、运行与出错设计。
- 用 ASCII/流程图、时序图、ER 图代替界面。
- 程序鉴别材料开篇写「由后端程序源代码组成」。
- 确无任何操作界面（含管理端）时，告知用户可另备盖章《无操作界面说明》；名称宜体现「服务 / 接口 / 嵌入式」等，避免叫「…小程序/APP」却声称无界面。

若「后端 API + 独立小程序」但**登记名称是小程序**：仍按有界面处理，截小程序，不截 API。

## 4. 《软件名称说明》（其他相关证明文件）

软件全称里出现**非功能描述的专有词**（自创中文品牌、音译、外文标识）时，审查可能要求解释「是什么意思、为何取此名，并保证不涉及他人名称、商标或标识，申请人签章」。

| 情况 | 上传什么 |
|------|----------|
| 该词已是申请人在中国大陆的**注册商标** | **商标注册证**（不要再写「尚未注册」） |
| 不是注册商标，或关联企业商标、自创音译 | 《软件名称说明》打印后**公章鲜章**，扫 PDF |

说明须含：流水号（若已有）、全称/简称/版本、申请人；拆开全称各段含义；专名含义与取名由来；保证不侵犯第三人名称/商标；签章与日期。  
草稿用 `assets/软件名称说明.template.md` 复制到工作目录 `软件名称说明.md`；**本 skill 不代签章**。  
全称、简称须与申请表、鉴别材料首页**完全一致**。

**Contrast — 名称：**

- Correct：专有词逐字说明 + 与英文标识对应关系 + 保证不涉及他人标识 + 鲜章
- Incorrect：只改说明书正文、不交证明文件；或已有商标证却写「尚未办理商标注册」
- Rationale：通知书要求的是「其他相关证明文件」，不是改一句话

## 5. 对照

**Contrast — 要不要截图：**

- Correct：小程序/APP → 真机连贯截图；纯 API 服务 → 设计说明书 + 流程图，无假 UI
- Incorrect：所有项目都省略截图；或纯后端去截无关网页冒充本软件
- Rationale：截图义务跟**有无人机界面**走，不跟「是不是软著」一刀切

**Contrast — 有 UI 的说明书：**

- Correct：概述后即有总览截图；流程章逐步截图；每图 3～5 句
- Incorrect：第 8 章只写「页面布局为…」而无图；或把全部图堆在 `-5.md` 文末；或只用 ASCII 线框
- Rationale：这是「缺少软件运行截图」补正的典型成因

### 其他高频补正（交付时对照）

| 补正意见（摘要） | 根因 | 预防 |
|------------------|------|------|
| 文档缺少运行截图 | 操作手册路线却无真实截图 | 见本章 §2 |
| 文档应提交详细操作手册或设计说明 | 内容单薄、套话 | 背景/流程写厚；有 UI 配真机图 |
| 文档与源程序内容不符 | 说明书写了代码里没有的功能 | 忠于选中源码 |
| 软件名称不一致 | 申请表 vs 页眉 vs 截图 vs 首页三行 | 全链路统一 `基础资料.md` |
| 截图与申请操作系统不符 | 如申请小程序却交无关桌面图 | 平台与申请表一致 |

## 6. 补正办理（已下发通知书时）

1. 只改通知书点名的项；不要顺手改程序鉴别材料（除非同时被点名）。
2. 第 1 条名称 → 证明文件栏上传盖章说明或商标证。
3. 第 2 条缺截图 → 按第 2 节补图后**整本替换**文档鉴别材料 PDF（页眉名称版本不变）。
4. 重导时加 `--only`，避免覆盖未点名的那份：
   ```bash
   python SKILL_ROOT/scripts/md2docx.py --workdir docs/软著登记申请 --only document
   python SKILL_ROOT/scripts/export_identification_pdf.py --workdir docs/软著登记申请 --only document
   ```
5. 若 Word 正打开 `文档鉴别材料.docx`，脚本会另存 `文档鉴别材料-重新生成.docx`。关掉占用后再覆盖正式文件名，或直接用另存稿出 PDF。
6. 导完必须打开 Word/PDF 看图：完整界面，不是细横条。
7. 30 日内提交；逾期视为撤回。

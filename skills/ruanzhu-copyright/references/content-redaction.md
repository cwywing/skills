# 内容脱敏与路径规范（强制）

Phase 0 配置、Phase 2b/3 写作、Phase 4 转 Word **之前**必须遵守。违反则材料不可交付。

---

## 1. 项目路径：禁止本机绝对路径出现在「对外材料」

| 位置 | 规则 |
|------|------|
| `基础资料.md` → `# config` → `后端/前端项目根目录` | 优先填 **相对路径**：`.`（仓库根，且从仓库根执行脚本）或相对仓库根的子目录；**禁止**把 `C:/Users/...`、`/home/...`、含中文用户目录的盘符路径写进将对外展示的叙述 |
| `document_identification-*.md` | **禁止**任何本机绝对路径 |
| `program_identification-*.md` / docx | **禁止**页眉页脚、说明段写入绝对路径；源码正文若含路径字符串，转 Word 前用脱敏脚本替换 |
| `codebase_data.json` 的叙述字段 | 不写入绝对路径；`software_info` **不要**把著作权人单位全称当作说明书正文素材回灌 |

**Correct：** `后端项目根目录: .`  
**Incorrect：** `后端项目根目录: C:/IT课@某人/wwwroot/proj`  
**Rationale：** 绝对路径对审查无意义，且泄露内部目录结构与人员信息。

脚本仍须能解析根目录：从**仓库根**执行 `python ... --workdir docs/软著登记申请`，`.` 即指向仓库根。

---

## 2. 单位名称：申请表可有；首页说明署名义须写，正文默认不再重复

| 字段/位置 | 规则 |
|-----------|------|
| `基础资料.md` 中 `著作权人` | 可填真实单位/个人（申请表需要） |
| 程序/文档鉴别材料**首页 `## 说明`** | **必须**写三行：`权利人署名` / `软件名称` / `软件版本号`，与申请表完全一致 |
| 文档鉴别材料其余正文、附录、故事、背景 | **默认不写**单位全称；用「本系统」「建设方」等中性表述 |
| 用户明确要求「说明书写上公司名」 | 才写入正文，并仅出现在概述信息表，不在每个章节重复 |

**Correct（首页）：**  
`权利人署名: 某某有限公司`  
`软件名称: XXX管理系统`  
`软件版本号: V1.0`

**Incorrect：** 正文各章反复写单位全称；或首页署名与申请表不一致。

转 Word 前：`redact_materials.py` 会脱敏正文中误写的著作权人字符串，但**保留**以 `权利人署名:` 开头的行。

---

## 3. 其它脱敏（与密钥同等对待）

交付前扫描并处理：

- 密钥、密码、APP_KEY、Token、Secret（脚本已滤一层，仍须抽查）
- 生产完整 URL、内网主机名（可改为 `[URL已省略]`）
- 真实邮箱（`[邮箱已省略]`）
- 源码注释/示例 JSON 中的真实姓名（导出材料中改为 `[人员已省略]`，**不改仓库业务源码**，只改 `md素材/program_identification-*.md`）

---

## 4. 强制命令（Phase 4 前）

```bash
python SKILL_ROOT/scripts/redact_materials.py --workdir <workdir>
```

然后才运行 `md2docx.py`。`redact_materials.py` 会：

1. 读取 `基础资料.md` 中的著作权人（若有），从文档 MD 中去除/替换；
2. 将 Windows/Unix 绝对路径模式替换为 `[本地路径已省略]`；
3. 对程序 MD 做路径与常见示例人名占位（可配置）。

Agent **不得跳过**本步骤，除非用户明确说「保留公司名与绝对路径」。

---

## 5. 自检

在 `md素材/` 与两个 docx 中搜索（除 `基础资料.md` 的著作权人配置行、以及材料首页 `权利人署名:` 行外）不应命中：

- `C:/`、`C:\\`、`/Users/`、`/home/`
- 著作权人全文散落在正文叙述中（首页署名行除外）
